# Blog Management Cheat Sheet

Cheat sheet for managing this blog. It runs on **fastpages** (a Jekyll 4.1 template from fast.ai) and is published with **GitHub Actions to GitHub Pages**.

Live site: https://GeileHirnbude.github.io/notes-of-a-nerd/

---

## 1. The three ways to write a post

The repo converts sources in `_notebooks/` and `_word/` into finished posts in `_posts/`.

| You write/edit here | Converted into | Best for |
|---|---|---|
| `_notebooks/*.ipynb` (Jupyter) | `_posts/*.md` | Data science, charts, code with outputs |
| `_word/*.docx` (Word) | `_posts/*.md` | Long-form writing | 
| `_posts/*.md` (directly) | (used as-is) | Simple text posts |

**Filename convention (mandatory):** `YYYY-MM-DD-slug.ext`
e.g. `_posts/2023-05-14-hello-world.md` or `_notebooks/2023-05-14-my-analysis.ipynb`

> ⚠️ Never hand-edit files that start with `### THIS FILE WAS AUTOGENERATED! DO NOT EDIT!`. Those are converted from notebooks — edit the `.ipynb` source instead.

## 2. Writing a plain Markdown post (simplest)

Create `_posts/YYYY-MM-DD-slug.md` with frontmatter at the top:

```yaml
---
toc: true
layout: post
description: A short subtitle shown under the title.
title: My Great Post
categories: [tech]
image: images/logo.png
comments: true
---
```

Then write the body with regular Markdown. Start with a `# Heading`.

### Common frontmatter keys

| Key | Meaning |
|---|---|
| `title` | Post title. **Quote it** if it contains `:` `~` `*` (e.g. `title: "Monge-Elkan: a story"`), otherwise Jekyll may crash. |
| `description` | Subtitle / blurb under the title |
| `categories: [a, b]` | This is the "tags" system → shows under `/categories/` |
| `toc: true` | Auto table of contents |
| `comments: true` | Enable comments (utterances) |
| `image: images/x.png` | Preview/social image (show it with `show_image: true` in config) |
| `hide: true` | Hide from home + tags pages (poor-man's draft); URL still resolves |
| `search_exclude: true` | Exclude from site search |
| `sticky_rank: N` | Pin post to top of the home list |
| `author: Name` | Author shown in post meta |
| `modified_date` | Renders "~ date" next to publish date |
| `permalink: /custom/` | Override the URL |

### Useful Markdown bits
- Images: `![]({{ site.baseurl }}/images/logo.png "caption")`
- Video: `{% include video.html url="https://..." %}`
- Callout boxes:
  - `{% include alert.html text="..." %}`
  - `{% include info.html text="..." %}`
  - `{% include note.html content="..." %}`, `tip.html`, `warning.html`, `important.html`
- YouTube: `{% include youtube.html %}`
- Twitter: `{% twitter <url> %}`
- Footnote: `{% fn 15 %}` in text, `* {{ "text" | fndetail: 15 }}` at the end

## 3. Writing a notebook post (`.ipynb`)

Put a Jupyter notebook in `_notebooks/YYYY-MM-DD-slug.ipynb`.

**Cell 0 (top markdown cell)** carries the metadata as `- ` dashed lines:

```markdown
# My post title
> Short subtitle / description.

- toc: true
- badges: false
- comments: true
- categories: [science]
- image: images/chart-preview.png
```

**Code cell flags** (first line of a code cell):
- `#hide` — hide input and output
- `#hide_input` — hide input only (keeps output)
- `#collapse-hide` — collapsible, collapsed
- `#collapse-show` — collapsible, expanded

**Images in notebooks** are referenced relative to the notebook and auto-copied to `images/copied_from_nb/` at build time. Do **not** hand-place images in `images/copied_from_nb/` — they can be deleted on rebuild.

---

## 4. Writing a Word post (`.docx`)

Put a `.docx` file in `_word/YYYY-MM-DD-slug.docx`. It's converted with pandoc. Extracted images land in `assets/img/<post-basename>/media`.

## 5. Preview locally

Everything runs in Docker.

```bash
make server            # live preview at http://127.0.0.1:4000  (kills other containers first)
make server-detached   # same, but in background
make convert           # ONLY convert notebooks + Word -> _posts/*.md
make quick-build       # cached rebuild
make build             # full no-cache rebuild
make stop              # stop containers
make bash-jekyll       # shell into the Jekyll container
make bash-nb           # shell into the converter container
```

- The site does **not** auto-refresh in the browser — refresh manually.
- Jupyter is also served at `http://127.0.0.1:8080` (no password) when containers run.
- `make convert` regenerates the `_posts/*.md` files from your notebooks before you preview.

**No Docker, no problem:** `bundle install && bundle exec jekyll serve` (needs local Ruby + the gem set).

## 6. Publishing / deploying

Deployment is automatic via GitHub Actions — **you only need to `git push` to `master`.**

```bash
git add -A
git commit -m "Add new post"
git push origin master
```

On every push to `master`, the `ci.yaml` workflow:
1. Converts notebooks + Word docs to posts
2. Builds the Jekyll site
3. Deploys the generated `_site/` to the `gh-pages` branch → site goes live
   (usually takes a minute or two, watch the "Actions" tab)

Pull requests only build/test — they do **not** deploy.

> The workflow needs a GitHub repo secret called `SSH_DEPLOY_KEY` (a deploy key with write access to the repo). If pushes never trigger a deploy, check that this secret exists in **Settings → Secrets**.

## 8. Editing the site itself (config/settings)

Main settings live in `_config.yml` (site title, description, social links, pagination, math, analytics). Things that are still default/fastpages branding — likely want changing:

| What | Where |
|---|---|
| Site `title: fastpages`, `description` | `_config.yml` |
| Social links (`twitter: fastdotai`, `github: fastai`) | `_config.yml` → `minima.social_links` |
| Home page marketing copy | `index.html` |
| About page | `_pages/about.md` |
| `baseurl` must match | `_config.yml` and `_action_files/settings.ini` (both `/notes-of-a-nerd`) |

Other pages: `_pages/about.md`, `_pages/tags.html` (→ `/categories/`), `_pages/search.html` (→ `/search/`), `_pages/404.html`.

## 9. Optional features (config flags)

- **Math (KaTeX/MathJax):** set `use_math: true` in `_config.yml`. Delimiters: `$$...$$`, `$...$`
- **Search:** built-in lunr search at `/search/`
- **RSS:** auto at `/feed.xml`; `sitemap.xml` and `robots.txt` auto-generated
- **Comments:** add `comments: true` to a post — requires the **utterances** GitHub App installed on the repo
- **Citations:** jekyll-scholar is installed (uses `_bibliography/references.bib`). Usage:
  ```
  {% cite buch2020metric %}
  {% bibliography --cited %}
  ```
  Add a `scholar:` block to `_config.yml` to pick a CSL style (e.g. `acm-sig-proceedings`, files already at repo root).

## 10. Gotchas / troubleshooting

- **Malformed YAML frontmatter** → build fails with `strict_front_matter`. Quote any title containing `:`, `~`, `*`.
- **jekyll-scholar in CI:** the CI workflow pulls upstream `fastai/fastpages-jekyll` from Docker Hub, which does **not** include jekyll-scholar. If CI builds fail on "jekyll-scholar not installed", the workflow/`_config.yml` needs adjusting (e.g. a custom Docker image built with it, or remove the plugin).
- **future: true** is set in config, so a future-dated post is still published — you can't hide a post by dating it in the future; use `hide: true` instead.
- **Duplicate posts:** leftover `*-Copy1.md` files render as real posts — delete them.
- **Do not edit `images/copied_from_nb/`** — auto-managed at build time.
- **fastpages is archived upstream** — no new updates will come. It still works fine, but plan if you want long-term migration.
